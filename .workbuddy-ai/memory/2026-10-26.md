### 诊断结论（用户认可）

原提示词的三个问题：
1. 「用于演示」被写成「功能精简稳定」，整份文档气质是防 AI 乱加功能，不是描述产品

3. 硬拿「浏览器书签」做对比，但 RSS 与书签不是同类产品；真正的差异（内容推送到你面前）被「禁推送」堵死，只好拿「全局搜索」当卖点，而搜索是 RSS 标配

### 技术要点

- rssparser 6.0.4 API 与文档不一致：`RssParserBuilder(client, Charsets.UTF_8).build()`，
  模型类叫 `RssChannel`/`RssItem`（不是 `Parser`/`Channel`/`ArticleItem`）。
  用 javap 解 AAR 才确认，没靠记忆
- Room：外键 CASCADE + `(feedId, link)` 唯一索引 + `OnConflictStrategy.IGNORE`，
  刷新不重置已读
- 日期：5 个源实际格式全是 RFC 1123 变体，已用 jshell 验证解析覆盖
- HTML 清洗（`Html.fromHtml`）必须放 IO/Default 线程，否则 60 条一起处理会卡首帧
